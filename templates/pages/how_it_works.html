The pipeline

Uploaded files, batch uploads and live microphone windows all follow these steps.

  1. Capture or upload

    A WAV, MP3, FLAC, OGG or M4A file is uploaded, or the browser sends a 3-second microphone window after you allow microphone access.

  2. Validate

    Format, size, length (0.3–60 s) and decoding are checked. Silent, damaged and unsupported files are rejected with a clear message, and exact duplicates are detected by SHA-256 hash.

  3. Check quality

    Silence ratio, clipping ratio and signal level (RMS) give a quality label: Good, Acceptable, Poor or Unusable.

  4. Preprocess

    The audio is converted to mono, resampled to 22.05 kHz, trimmed of silence, and the loudest 3-second window is selected, normalised and padded to a fixed length.

  5. Python model

    A custom CNN reads a 128-band log-mel spectrogram of that window and gives a confidence for each of the 10 classes.

  6. Teachable Machine model

    The same window is resampled to 44.1 kHz and turned into the FFT features Teachable Machine uses. Its exported model classifies ~1-second slices, which are averaged by loudness. It never sees the Python result.

  7. Compare

    The predicted classes, top-class confidence difference and top-two margins are compared, giving Acceptable Match, Weak Match, Model Disagreement or Uncertain Result.

  8. Decide

    A weighted average of the two score sets produces the final class. Rules then set severity, raise an alert, or send the event to manual review.

  9. Store and follow up

    The event, both raw model outputs, the comparison and every later action are saved. Reviewers can correct a class without erasing the original result.

Questions

Why do the two models sometimes give different answers?

They are different kinds of model trained with different tools and features. Disagreement is useful information: it usually means the sound is ambiguous, noisy or under-represented in training, so it goes to a person.

Can a model's answer be changed after the fact?

No. The original outputs of both models are stored unchanged. A reviewer's confirmation or correction is saved as a separate action with a comment and a timestamp.

What happens to live microphone audio?

Each window is classified and the temporary file is deleted immediately. Live windows are not saved to event history.

Why is only a 3-second window classified in a long clip?

Both models were trained on short clips. The loudest 3-second window usually contains the event. The page says so whenever a clip is longer than 3 seconds.
